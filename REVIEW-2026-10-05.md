# REVIEW-2026-10-05.md — third AI review (before the first public release)

**Date:** 5 Oct 2026 · **Code:** Signer commit `a193d86`, Hub commit `5baf099`
**How:** four independent AI reviewers, each one area, none of them saw how
the code was written: (1) cryptography and key storage, (2) reading and
signing transactions, (3) Android and app-to-app, (4) supply chain, release
process and whether the documents' claims are true. Claude then re-checked
the most important findings against the code. All 108 automatic tests pass.
The previous review is REVIEW-2026-10.md (1 Oct).

## In short

**No way was found to steal funds remotely, or for an ordinary harmful app
to sign without the user's password or fingerprint.** The cryptography is
sound (24-word phrase from the phone's secure random source, Klever's own
derivation path, scrypt 2^17, AES-256-GCM, no nonce reuse), the
transaction reader matches Klever's own definitions field for field and
survived 300,000 random mutations without showing one thing and signing
another, mainnet is refused, answers can only go back to the asking app,
and nothing secret was ever committed to git.

What's left falls into two groups:

1. **Before the public GitHub release:** mostly housekeeping: the licence
   (the only licence file is still Expo's MIT template), the version number
   Android uses for updates, a stricter release check, and outdated
   sentences in the documents.
2. **Security hardening, ideally before mainnet:** the most important is
   *accessibility malware* (the standard banking-trojan technique): on
   Android 12 and 13 an app the user has given accessibility access could
   read the screens and press the buttons, including typing the password
   if it learned it. The Signer only warns about such apps today.

### B. Security hardening

| ID | Sev. | Finding | Fix |
|---|---|---|---|
| A1 | High | **Accessibility malware.** Signer screens are hidden from non-tool accessibility apps only on Android 14+; on 12/13 any enabled accessibility app can read and press everything. "Allow this app" needs no password. Such an app, if it learned the password, could send its own request, allow it, type the password and the address ending, and approve. (Fingerprint can't be automated.) Today the Signer only warns. Requires the user to have granted accessibility access to the harmful app. | When an accessibility app is on that didn't come with the phone (and isn't a known tool like TalkBack): allow signing only with fingerprint, or block; on Android 12/13 block. Require password/fingerprint for "Allow this app" and when an allowed app's certificate changed. |
| A2 | Medium | The root/bootloader block **fails open** when Android returns nothing (empty report, empty boot state): no finding → signing stays on. Root signs are also easy to hide (Magisk DenyList). | Treat "no answer" as "couldn't check" (signing off). Later: hardware key attestation (Android's chip itself reports bootloader state). |
| C1 | Medium | Passwords rated "weak" (e.g. `password1234`, `111111111111`) are accepted; only the 12-character minimum is enforced. Matters if the phone is rooted/exploited and the password can be guessed offline. | Refuse "weak"; consider "fair" or 16+ before mainnet. |
| T1 | Medium | Token amounts are shown as long ungrouped "units" (e.g. `1000000000000000000 units of USDT-ABCD`) and no rule looks at token amounts; the KLV amount rule is off by default. An inflated amount could slip through. | Group digits; optional token decimals; per-token amount rule; KLV threshold on by default (e.g. 100 KLV). |
| T2 | Medium | Klever tokens/NFTs can carry **royalties** set by their creator, paid by the sender on transfer; the offline Signer can't see them and the fee shown doesn't include them. (To confirm on testnet.) | Fixed note on every non-KLV transfer; document it. |
| T3 | Medium | The 6 typed characters are the address's **last** 6, which are its checksum: the cheapest part for a scammer to fake (a look-alike address matching them takes minutes to generate). | Ask for a randomly chosen group from the middle instead (outline that box). |
| C4 / A7 | Low | The Restore screen suggests pasting the 24 words; they then stay in the clipboard and keyboard clipboard history. | Remove the tip, or clear the clipboard after a paste and say so. |
| A3 | Low | If Android recreates the main screen (font-size or language change), screenshot blocking isn't re-applied on screens without secrets (Home, Settings…). | Set it natively each time the Signer comes to the front. |
| A4 | Low | `taskAffinity` hardening (older task-hijacking variants on unpatched phones). | Config plugin: `taskAffinity=""`. |
| A5 | Low | No idle auto-lock; split-screen never locks. Signing still needs the password. | Lock after a few idle minutes / in split-screen. |
| T4 | Low | One tiny transfer makes an address "known" forever (no new-receiver prompt later). | Show history on the approval screen; minimum amount or per-app "known". |
| T5 | Low | "First request from an app" is remembered by app name only, survives removal and certificate change. | Key by name + certificate; clear on removal. |
| T6 | Low | No duplicate/old-nonce awareness ("it failed, approve again" double payment). | Warn on a recent identical transfer and far-future nonces. |
| T7 | Low | Mainnet refusal hangs on one setting; no test asserts the shipped build is testnet. | Test + release-check step. |
| T8 | Low | Note filter still lets a few blank-looking/overlaying characters through (notes are boxed and labelled "not checked"). | Tighten the allow-list. |
| C2 | Low | Very early wallets keep the lighter password setting while fingerprint is on. | Upgrade anyway, re-save fingerprint copy. |
| C3 | Low | Some copies of secret bytes in memory aren't wiped (library internals). | Wipe where possible; correct comments. |
| C5 | Low | No tests for the password-check sequence and storage write order. | Extract and test. |

## Checked and found correct (selection)

- Phrase, derivation, scrypt, AES-GCM, associated data, no downgrade; wrong-password counter counts *before* checking and uses a clock that can't be changed.
- Fingerprint copy needs strong biometrics on every use; Android disables it when a fingerprint is added.
- Transaction reader: unknown/duplicate/out-of-order fields, overflowing numbers, anything that doesn't re-encode byte for byte, and every non-transfer type are refused; Klever's signing scheme (Ed25519 over blake2b-256 of the raw data) confirmed; mainnet (108) refused.
- Caller identity from Android, one request at a time, answers only to the caller, nothing logged, no intent filter on the request screen.
- Every unlocked or request screen locks when the Signer goes to the background.
- No internet permission; backups off; overlays hidden; autofill off.
- Hub: seal check before every request, fails closed, correct Android API.
- Nothing secret in the git history; all packages from the official registry with integrity hashes; crypto packages pinned; official key fingerprint identical in all 8 places.
