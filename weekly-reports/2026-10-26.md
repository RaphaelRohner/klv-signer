**Code changes (19–25 Oct) and review**

What changed: the 19 Oct fixes, the example app 0.1.3 (several NFTs in one transaction) and Signer 0.1.3, which can now sign a short text (SIGN_MESSAGE) and isn't released yet. Four separate reviews covered crypto, what gets signed, Android/app-to-app with the example app, and docs. They found no High or Medium problems.

Confirmed by the reviewers:

* Signing a text goes through all the same checks as a transaction: allowed apps, the unsafe-phone block, fingerprint-only mode and wrong-password counting.
* A signed text can never be used as a transaction signature.
* The key is wiped after use.

Low points:

* **Low (I checked this one myself):** pressing the phone's Back button on the "sign this text?" screen isn't handled. The request still fails safe, but the calling app is told "you left the Signer" instead of "rejected". It's a one-line fix in App.js.
* **Low:** some odd characters still pass the text check. Strike-through or stacked marks, unusual spaces and many blank lines can make a text hard to read. They can't hide or reorder anything.
* **Low:** a signed text isn't tied to the app that asked for it. An allowed app could pass on another service's sign-in text. This is how Klever's message format works, and it's already listed as "Partly" in SECURITY.md. Services checking such signatures should include their name and a one-time number in the text.
* **Low:** the example app's "pass a request on" test screen ships in every example build. It's harmless (it can't be opened from outside and only asks for the address), but someone copying the example would copy it too.
* **Low, docs:** SECURITY.md still says "Last updated 19 Oct" and its history rows are out of date order. SIGNER-PROTOCOL.md's sample code and intro don't mention SIGN_MESSAGE yet. Section 3c doesn't say the public key comes from decoding the address.
* **Low, not security:** the password checker's table of shifted symbols uses German/Swiss key positions even for English keyboards. The only effect is a slightly wrong "neighbouring keys" score for some passwords.

**Still open from earlier:** OPEN-FINDINGS.md lists nothing as open, and the 19 Oct fixes do appear in the code.
